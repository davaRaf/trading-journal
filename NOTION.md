# Перенос журнала из Notion

Человек уже год ведёт журнал в Notion. Руками он сюда двести сделок не перенесёт —
значит, не станет пользоваться. Поэтому переносим за него: сделки, заметки со страниц
и скриншоты.

Открыть: сайдбар → **Імпорт** → вкладка **Notion**. Плюс окно один раз само
всплывает после входа — чтобы новичок не сидел перед пустым экраном.

## Что человек делает руками

Ровно три шага, они же написаны в самом окне:

1. `notion.so/my-integrations` → **New integration**, тип **Internal**
2. скопировать **Internal Integration Secret** (начинается на `ntn_`)
3. открыть свою базу сделок → **···** → **Connections** → добавить эту интеграцию

Третий шаг обязателен: без него Notion не покажет базу вообще. Это самая частая
причина «баз не видно» — в тексте окна про это сказано отдельно.

## Что делаем мы

**Сами угадываем колонки.** `guess_mapping()` в `notion_import.py` сопоставляет
колонки Notion с полями журнала по названию и типу. Словарь подсказок трёхъязычный
(укр/рус/англ) — журналы ведут кто на чём. На тестовой базе угадывается 14 из 15.
Что не угадалось — человек поправляет выпадашкой, там же видит превью пяти строк.

**Приводим значения к нашему виду.** `long`, `Лонг`, `buy` → `Long`.
`TP`, `Win`, `Прибыль`, `+` → `Win`. `1:2.5` → `2.5`. `12.02.2026 16:00` →
`2026-02-12T16:00`. Всё это в `NORMALIZE` — если попадётся новая запись, дописывать туда.

**Забираем заметки со страницы.** В Notion заметки чаще лежат не в колонке, а в теле
страницы. Читаем блоки и складываем в `notes`.

**Качаем скриншоты к себе.** Ссылки Notion на файлы живут около часа — откладывать
загрузку нельзя, тянем прямо во время импорта в `data/screenshots/`. Таймфрейм
угадываем по имени файла и подписи (`shot-15m.png` → `15m`).

**Новые инструменты подхватываем.** Если в базе есть `XAUUSD`, которого у нас не было,
он попадает в статистику сразу, а в подсказки формы новой сделки — через
`localStorage['statsai_pairs']`.

**Не задваиваем.** У каждой перенесённой сделки хранится `notion_id`. Повторный импорт
той же базы добавит только новое, остальное посчитает пропущенным.

## Где что лежит

| Файл | Что |
|---|---|
| `notion_import.py` | весь разговор с Notion: чтение, угадывание колонок, приведение значений, загрузка картинок |
| `app.py` | маршруты `/api/notion/*` и хранение ключа |
| `static/notion.js` | окно мастера: ключ → база → сверка колонок → перенос |
| `static/import.css` | стили окна |
| `data/notion.json` | ключ доступа. **В репозиторий не кладётся** |

Родная вкладка «Файл» (CSV/JSON) осталась как была — Notion добавлен второй вкладкой
в то же окно, чужой код не тронут.

## Что надо знать

**Ключ живёт только на сервере.** В браузер не возвращается никогда — наружу отдаём
лишь название рабочего пространства.

**В демоверсии не работает.** Импорт ходит в сеть с сервера, а в демо сервера нет —
окно честно об этом говорит.

**Notion не любит спешку.** Больше трёх запросов в секунду — и он отвечает 429.
Держим паузу сами (`MIN_GAP`), на 429 ждём и повторяем. Из-за этого база на 500 сделок
со скриншотами переносится минутами, а не секундами — поэтому импорт идёт в фоне
с полосой прогресса, а не одним запросом.

## Чего пока нет

**Вход через кнопку «Connect Notion».** Сейчас человек вставляет ключ руками.
Для продукта нужна публичная OAuth-интеграция: тогда будет одна кнопка → выбор страниц
на стороне Notion → готово. Требует зарегистрированного приложения и домена.

**Обратной синхронизации.** Переносим один раз в одну сторону. Новые сделки в Notion
подтянутся следующим импортом (старые не задвоятся), но правки существующих — нет.

## Как проверить без Notion

Есть двойник API — `tests/fake_notion.py`. Поднимается на 8899 и отвечает как настоящий
Notion, включая картинки и текст страниц. В двух окнах:

```bash
python tests/fake_notion.py
```

```bash
NOTION_API=http://127.0.0.1:8899/v1 python app.py
```

Ключ для двойника — `secret_good`, любой другой даёт ту же ошибку, что и настоящий Notion.
