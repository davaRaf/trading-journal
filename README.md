# Trading Journal

Локальный журнал сделок: записываешь сделку — статистика за день, месяц, квартал и год пересчитывается сама.
Работает на своём компьютере, данные никуда не уходят.

## Что нужно

Только **Python 3.8+**. Никаких библиотек ставить не надо — используется стандартная библиотека.

Проверить, стоит ли Python:

```bash
python --version
```

## Запуск

**Windows:** двойной клик по `start.bat` — сам откроет браузер.

Вручную, из папки проекта:

```bash
python app.py
```

Потом открыть **http://localhost:8172/**

Окно с сервером не закрывать, пока работаешь с журналом.

## Что умеет

- **Dashboard** — статистика текущего месяца сверху, весь год ниже
- **Journal** — календарь месяца: каждый день покрашен по результату, значки TP / SL / BE− / BE+, панель выбранного дня
- **Quarterly** — четыре квартала, лучший и худший месяц внутри каждого
- **Yearly** — год целиком, клик по месяцу открывает подробный разбор
- **Analytics** — срезы по инструменту, сессии, направлению, модели входа, биасу, сетапу, ошибкам
- Скриншоты графиков по таймфреймам (1m … 4H), вставка из буфера через `Ctrl+V`
- Картинка со статистикой месяца в один клик — чтобы поделиться
- Импорт из CSV или JSON, экспорт всех сделок
- Светлое оформление

## Как считается результат

Всё в процентах от депозита:

| Итог | Сколько даёт |
|---|---|
| **TP** | риск × RR |
| **SL** | минус риск целиком |
| **BE−** | 0% — безубыток, дальше цена пошла против |
| **BE+** | 0% — безубыток, но цена дошла бы до цели |

Рискнул 1.5% и словил стоп — это −1.5%. Рискнул 1% при RR 2.5 и взял тейк — это +2.5%.

Разделение **BE− / BE+** нужно, чтобы посчитать, выгоден ли перенос стопа в безубыток:
сколько он спас против того, сколько отнял.

**Тип входа** считается сам: вошёл по биасу дня — Continuation, против биаса — Reversal.
Можно переопределить вручную.

## Где данные

```
data/trades.json        все сделки
data/screenshots/       картинки графиков
```

Резервная копия — скопировать папку `data` целиком.
В репозиторий данные не попадают, они в `.gitignore`: у каждого свой журнал.

## Структура

```
app.py                    сервер: отдаёт файлы и хранит сделки (только стандартная библиотека)
static/index.html         разметка приложения
static/app.js             вся логика и расчёты
static/share.js           картинка статистики за месяц
static/style.css          оформление
static/demo.js            демо-режим: хранение в браузере, когда сервера нет
static/demo-data.json     вымышленные сделки для демо
tools/make_demo_data.py   генератор этих сделок
vercel.json               настройки публичного демо на Vercel
```

## Совместная работа

```bash
git clone <адрес репозитория>
cd trading-journal
git checkout -b моя-ветка
# правишь, проверяешь через python app.py
git add -A && git commit -m "что сделал"
git push -u origin моя-ветка
```

Дальше — pull request, чтобы изменения посмотрели перед вливанием в `main`.


## Демо-режим и публичное демо

Журнал умеет работать **без `app.py`**. Если сервер не отвечает, приложение
переключается в демо-режим: сделки хранятся прямо в браузере посетителя
(`localStorage`), в правом нижнем углу появляется плашка «Демо».

Зачем это нужно:

- **общая ссылка для нас двоих** — видеть правки интерфейса, не запуская ничего у себя;
- **превью на каждую ветку** — Vercel собирает отдельный адрес для каждого pull request;
- **«попробовать без регистрации»** для будущих пользователей.

При первом заходе подгружаются 150 вымышленных сделок из `static/demo-data.json`.
Кнопка «Сбросить» на плашке возвращает демо в исходное состояние.

Локальный запуск через `app.py` работает как раньше — демо-режим там не включается
и в `localStorage` ничего не пишет.

### Что важно знать

- **Реальные сделки в демо не попадают.** `demo-data.json` — сгенерированный набор.
  Пересобрать: `python tools/make_demo_data.py`
- **Скриншоты в демо не сохраняются** — в браузере на них не хватает места
  (лимит несколько мегабайт). Работают только в локальной версии.
- Бесплатный тариф Vercel (Hobby) — для некоммерческого использования.
  Когда появятся платные подписки, нужен платный тариф.

### Как подключить Vercel

1. [vercel.com](https://vercel.com) → войти через GitHub.
2. **Add New → Project** → выбрать репозиторий `trading-journal` → **Import**.
3. Framework Preset — **Other**. Остальное не трогать: настройки берутся из `vercel.json`.
4. **Deploy**.

Дальше Vercel сам пересобирает демо при каждом пуше в `main` и делает отдельную
ссылку-превью для каждого pull request.
