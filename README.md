# Trading Journal

Локальный журнал сделок: записываешь сделку — статистика за день, месяц, квартал и год пересчитывается сама.
Работает на своём компьютере, данные никуда не уходят.

## Что нужно

**Python 3.8+** и **база данных Postgres**. С тех пор как появились аккаунты, сделки
лежат в базе, а не в файле — без строки подключения журнал не запустится.

```bash
python --version
pip install -r requirements.txt
```

Дальше — база. Бесплатной хватает с запасом:

1. [neon.tech](https://neon.tech) → войти → **Create project**
2. `Dashboard → Connection string` → скопировать строку
3. скопировать `.env.example` в `.env` и вставить её в `DATABASE_URL`

Остальное в `.env` можно не заполнять: `SESSION_SECRET` сгенерируется сам,
без `BOT_TOKEN` сайт работает — не будет только напоминаний в Telegram.

Проверить, что всё сошлось:

```bash
python app.py
```

Если пишет `DATABASE_URL не задан` — не заполнен `.env`. Если ругается на `psycopg` —
не выполнен `pip install -r requirements.txt`.

## Две копии журнала

Личный журнал и рабочую копию держим раздельно, чтобы эксперименты не задели реальные сделки.

| | Личный журнал | Рабочая копия |
|---|---|---|
| Что внутри | реальные сделки | демо-сделки |
| Порт | 8172 | **8173** |
| Связь с GitHub | нет | есть |
| Запуск | `start.bat` | **`start-dev.bat`** |

Разработка идёт только в рабочей копии. Обе можно держать запущенными одновременно —
порты разные. Порт задаётся переменной `PORT`, по умолчанию 8172.

## Запуск

**Это рабочая копия — запускать через `start-dev.bat`**, двойным кликом.
Откроется **http://localhost:8173/**

`start.bat` (порт 8172) — для личного журнала с реальными сделками, он лежит
в отдельной папке и с этим репозиторием не связан. В рабочей копии его не трогаем.

Вручную, из папки проекта:

```bash
set PORT=8173 && python app.py
```

Окно с сервером не закрывать, пока работаешь с журналом.

## Что умеет

- **Огляд** — статистика текущего месяца сверху, весь год ниже
- **Журнал** — календарь месяца: каждый день покрашен по результату, значки TP / SL / BE− / BE+, панель выбранного дня
- **Аналітика** — срезы по инструменту, сессии, направлению, модели входа, биасу, сетапу, ошибкам
- **Новини** — экономический календарь на неделю, с разбивкой по важности и валюте
- **Перенос из Notion** — по обычной публичной ссылке, вместе с заметками и скриншотами. [Подробности](NOTION.md)
- **Калькулятор риска** — размер позиции под заданный риск, с ценой тейка по RR
- **Ссылки «поділитися»** — сделкой, днём, неделей, месяцем или годом, на выбранный срок
- **Темы оформления** — девять готовых плюс своя из двух цветов
- Скриншоты графиков по таймфреймам (1m … 4H), вставка из буфера через `Ctrl+V`
- Картинка со статистикой месяца в один клик
- Импорт из CSV или JSON, экспорт всех сделок

Что менялось в последнее время — в [CHANGELOG.md](CHANGELOG.md).

## Как считается результат

Всё в процентах от депозита:

| Итог | Сколько даёт |
|---|---|
| **TP** | риск × RR |
| **SL** | минус риск целиком |
| **BE−** | 0% — безубыток, дальше цена пошла против |
| **BE+** | 0% — безубыток, но цена дошла бы до цели |

Рискнул 1.5% и словил стоп — это −1.5%. Рискнул 1% при RR 2.5 и взял тейк — это +2.5%.

Разделение **BE− / BE+** нужно, чтобы посчитать, выгоден ли перенос стопа в безубыток:
сколько он спас против того, сколько отнял.

**Тип входа** считается сам: вошёл по биасу дня — Continuation, против биаса — Reversal.
Можно переопределить вручную.

## Где данные

Сделки, пользователи и привязки — **в базе Postgres**. На диске остаются только файлы:

```
data/screenshots/       картинки графиков
data/calendar/          архив экономического календаря
data/shares/            снимки для ссылок «поділитися»
```

Из них в репозиторий попадает только `data/calendar/` — накопленную историю
календаря взять больше негде, фид её не отдаёт.

**Старый `data/trades.json` больше не читается.** Если в нём остались сделки с прежней
версии, перенести их можно двумя способами: заново из Notion (кнопка «Підключити
Notion») или через **Імпорт → Файл**, скормив этот же `trades.json`.

Резервная копия — скопировать папку `data` целиком.
В репозиторий данные не попадают, они в `.gitignore`: у каждого свой журнал.

## Совместная работа

```bash
git clone <адрес репозитория>
cd trading-journal
git checkout -b моя-ветка
# правишь, проверяешь через python app.py
git add -A && git commit -m "что сделал"
git push -u origin моя-ветка
```

Дальше — pull request, чтобы изменения посмотрели перед вливанием в `main`.


## Демо-режим и публичное демо

Журнал умеет работать **без `app.py`**. Если сервер не отвечает, приложение
переключается в демо-режим: сделки хранятся прямо в браузере посетителя
(`localStorage`), в правом нижнем углу появляется плашка «Демо».

Зачем это нужно:

- **общая ссылка для нас двоих** — видеть правки интерфейса, не запуская ничего у себя;
- **превью на каждую ветку** — Vercel собирает отдельный адрес для каждого pull request;
- **«попробовать без регистрации»** для будущих пользователей.

При первом заходе подгружаются 150 вымышленных сделок из `static/demo-data.json`.
Кнопка «Сбросить» на плашке возвращает демо в исходное состояние.

Локальный запуск через `app.py` работает как раньше — демо-режим там не включается
и в `localStorage` ничего не пишет.

### Что важно знать

- **Реальные сделки в демо не попадают.** `demo-data.json` — сгенерированный набор.
  Пересобрать: `python tools/make_demo_data.py`
- **Скриншоты в демо не сохраняются** — в браузере на них не хватает места
  (лимит несколько мегабайт). Работают только в локальной версии.
- Бесплатный тариф Vercel (Hobby) — для некоммерческого использования.
  Когда появятся платные подписки, нужен платный тариф.

### Как подключить Vercel

1. [vercel.com](https://vercel.com) → войти через GitHub.
2. **Add New → Project** → выбрать репозиторий `trading-journal` → **Import**.
3. Framework Preset — **Other**. Остальное не трогать: настройки берутся из `vercel.json`.
4. **Deploy**.

Сервер на Vercel не едет — там только статика демо, см. следующий раздел.

Дальше Vercel сам пересобирает демо при каждом пуше в `main` и делает отдельную
ссылку-превью для каждого pull request.

### Чего на Vercel быть не может

Vercel запускает код только на время одного запроса — постоянного процесса там нет.
Поэтому туда едет **только демо**, а вот это работать не будет:

- **Telegram-бот.** `bot.py` держит длинное опросное соединение (`getUpdates`) —
  ему нужен процесс, который живёт всё время.
- **Перенос из Notion.** Двести сделок со скриншотами тянутся минутами, а функция
  на Vercel обрывается через десяток секунд.
- **Напоминания и вопрос про эмоцию.** Их шлёт фоновый поток по расписанию.
- **Аккаунты, база, скриншоты.** Файлы сохранять некуда, соединение с Postgres
  на каждый запрос открывать заново дорого.

Значит, схема такая: **Vercel — витрина (демо), боевой сервер — на другом хосте**.
Бесплатный вариант ниже.

## Как поставить боевой сервер на Render (бесплатно)

Один сервис держит и сайт, и бота: `RUN_BOT=1` запускает опрос Телеграма в том же
процессе. Второй процесс на бесплатном плане держать негде — воркеры там платные.

**1. База — Neon** (бесплатно, [neon.tech](https://neon.tech)):
войти → **Create project** → `Dashboard → Connection string` → скопировать строку.

**2. Сервис — Render** ([render.com](https://render.com)):

1. войти через GitHub → **New → Blueprint**;
2. выбрать репозиторий `trading-journal` — настройки берутся из `render.yaml`;
3. в **Environment** вписать:
   - `DATABASE_URL` — строка из Neon,
   - `BOT_TOKEN` и `BOT_USERNAME` — от [@BotFather](https://t.me/BotFather),
   - `GEMINI_API_KEY` — ключ для помощника (без него помощник молчит);
   `SESSION_SECRET` Render сгенерирует сам, `HOST=0.0.0.0` и `RUN_BOT=1` уже в файле;
4. **Apply** → через пару минут адрес вида `https://statsai.onrender.com`.

**3. Проверить:** открыть адрес — должна открыться страница входа; написать боту
в Телеграме `/start` — должен ответить.

### Что важно знать про бесплатный Render

- **Сервис засыпает после 15 минут без запросов.** Пока спит — бот не отвечает,
  а первый заход на сайт идёт секунд тридцать. Лечится бесплатным пингом
  (например, [uptimerobot.com](https://uptimerobot.com) раз в 10 минут на `/login`) —
  но это уже на грани правил Render, решать тебе.
- **Скриншоты лежат на диске сервиса**, а он на бесплатном плане пересоздаётся при
  каждом деплое — картинки пропадут. Записи о сделках останутся: они в Neon.
  Чтобы не терялись, нужен либо платный диск, либо хранилище вроде Cloudflare R2.

## Как поставить на Railway (так и сделано)

Railway держит `app.py` включённым всё время — это нужно и телеграм-боту, и переносу
из Notion. Ничего не спит, скриншоты остаются на месте. От $5 в месяц.

Живой адрес: **https://trading-journal-production-440c.up.railway.app**

### По шагам

1. [railway.com](https://railway.com) → войти через GitHub.
2. **New Project → Deploy from GitHub repo** → выбрать `trading-journal`.
   Сборка и старт берутся из `railway.json`.
3. **База:** `New → Database → PostgreSQL`. В сервисе приложения добавить переменную
   `DATABASE_URL` со значением `${{Postgres.DATABASE_URL}}` — это ссылка на соседний сервис.
4. **Переменные** сервиса приложения:

   | Переменная | Что это |
   |---|---|
   | `HOST` | `0.0.0.0` — иначе Railway не достучится до сервера |
   | `RUN_BOT` | `1` — телеграм-бот поедет в том же процессе |
   | `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
   | `BOT_USERNAME` | имя бота без `@` |
   | `GEMINI_API_KEY` | ключ помощника, [aistudio.google.com](https://aistudio.google.com) |
   | `SESSION_SECRET` | длинная случайная строка |

   `PORT` Railway подставляет сам. `DATA_DIR` нужен, только если хочется держать файлы
   на отдельном томе — **для скриншотов это не требуется, они в базе** (см. ниже).
5. **Settings → Networking → Generate Domain.**

### Тома не нужны

Скриншоты лежат в базе (`filestore.py`, таблица `files`), а файл на диске — только кэш.
У контейнера файловая система временная, и раньше картинки пропадали при каждом
обновлении кода. Теперь они едут вместе с базой: сменить хостинг — значит перенести
только её.

Накопленную папку перекладывает `python tools/shots_to_db.py` — один раз, повторный
запуск безопасен.

### GitHub должен видеть репозиторий

Если Railway пишет **«GitHub Repo not found»**, а список репозиториев пуст — приложение
Railway не установлено в GitHub. Ставится один раз:
[github.com/apps/railway-app/installations/new](https://github.com/apps/railway-app/installations/new)
→ **Only select repositories** → `trading-journal` → **Install & Authorize**.

После деплоя из CLI (`railway up`) автовыкладка выключается — включить обратно:
Settings → Source → **Auto deploy → Enable**.

### Перенос своих данных

Всё лежит в базе — и сделки, и скриншоты. Снять копию и залить в новую:

```
pg_dump -d "СТАРАЯ_СТРОКА" -Fc --no-owner -f dump.bin
pg_restore -d "НОВАЯ_СТРОКА" --clean --if-exists --no-owner dump.bin
```

До базы Railway можно дотянуться, не открывая её в интернет:

```
railway link
railway connect Postgres --tunnel-only
```

Понадобится SSH-ключ: `ssh-keygen -t ed25519`, потом `railway ssh keys add`.
